### Uso de sceMpeg / IPU

La libreria `libmpeg` del SDK esta enlazada dentro del ELF (la recomp la identifica en `work/game.toml`): `sceMpegInit@0x107AE8`, `sceMpegCreate@0x107B88`, `sceMpegAddBs`, `sceMpegGetPicture@0x107E08`, `sceMpegGetPictureRAW8(xy)`, `sceMpegReset`, `sceMpegClearRefBuff`, `sceMpegAddCallback@0x107FE8`, `_sceMpegFlush`, `_dispatchMpegCbNodata`, `_sendDataToIPU@0x108900`, `sceIpuInit/Sync/StopDMA/RestartDMA`. Esto es lo que el port tiene que reemplazar (o enlazar a stubs) en el nivel de la API `sceMpeg*`, no el de los registros IPU.

Llamadas desde codigo del juego (barrido de `jal` en el ELF; el nombre de funcion de los llamantes no es fiable porque `game.toml` no tiene simbolos del juego, solo direcciones):

| Llamada | Sitios | Direcciones |
|---|---|---|
| `sceMpegInit` | 1 | `0x172348` |
| `sceMpegCreate(mpeg, buf, size)` | 1 | `0x17248C`: buf = base+0x240000, size = `0x168800` (1,4 MB) |
| `sceMpegAddCallback` | 3 | `0x1724AC/CC/EC`: tipos 1, 2 y 3 |
| `sceMpegReset` | 2 | `0x171A44`, `0x171F1C` |
| `sceMpegGetPicture(mpeg, dst, 1280)` | 1 | `0x171E94` |

Lectura de esos argumentos:
- Tipos de callback 1, 2, 3 = Nodata, StopDMA, RestartDMA en el SDK **(hipotesis: numeracion de memoria del SDK publico)**. El callback Nodata es el que alimenta el IPU: la recomp ya lo trata asi (`kMpegCbNodata`, parche `patches/ps2recomp-mpeg-ipu-dma.patch`: el juego manda los bytes por **DMA canal 4 (toIPU)** y la recomp los captura).
- `sceMpegGetPicture` con 1280 = 40x32 macrobloques = 640x512: **un cuadro completo por llamada**, salida RGB32 (`sceIpuRGB32`). **(hipotesis)** que el tercer argumento sea el numero de macrobloques.
- No hay llamadas a `sceMpegDemuxPss*` / `sceMpegAddBs` desde el juego (solo la definicion dentro de la libreria): consistente con `.M2V` sin sistema PSS.

Consecuencia de diseno: `plat_video` es de **empuje** (el juego entrega bytes del flujo elemental, pide imagenes en orden de presentacion), no un reproductor de ficheros; el atajo de fichero existe para pruebas y para una ruta de "reproducir directamente" si M1/M2 prefieren saltarse el DMA.

La recomp (`third_party/PS2Recomp/.../Stubs/MPEG.cpp`, 2700 lineas) ya decodifica con FFmpeg (libavcodec + swscale), con relojes de presentacion y cola de callbacks muy atados a su modelo de rdram; no se reutiliza (ver licencias).

### Uso de sceMc*

`libmc` tambien va enlazada (`sceMcInit@0x1142F8`, `sceMcOpen@0x114658`, ... `sceMcGetEntSpace@0x115998`: las 19 funciones). El juego las llama desde un bloque contiguo de codigo propio `0x192490..0x194FA0` (sin nombres aun):

| Llamada | Sitios |
|---|---|
| `sceMcInit` | 1 (`0x192770`) |
| `sceMcSync` | 20 (en `sceMcInit` mismo y en todo el bloque: patron de orden + sync) |
| `sceMcGetInfo` | 2 (`0x1926B4`, `0x192D34`) |
| `sceMcGetDir` | 3 (`0x192490`, `0x194004`, `0x194514`) |
| `sceMcFormat` | 1 (`0x192B1C`) |
| `sceMcSetFileInfo` | 3 |
| `sceMcMkdir`, `sceMcDelete` x2, `sceMcRename` x2 | 1, 2, 2 |
| `sceMcOpen` / `Close` x2 / `Seek` / `Read` / `Write` / `Flush` | 1 / 2 / 1 / 1 / 1 / 1 |
| `sceMcChdir`, `sceMcUnformat`, `sceMcGetEntSpace` | 0 sitios directos |

Cadenas: `mc00:`, `mc10:` (rutas de tarjeta por puerto), `icon.sys`, `.ico`, `.dat`, `%s%s%s`, `SCES-50246`. Es decir: guarda en una carpeta propia del juego con `icon.sys`, un `.ico` y uno o mas `.dat`, y formatea, lista y renombra/borra. Falta (por no tener un guardado real) **(hipotesis)**: el nombre exacto de carpeta/fichero y los tamanos; `~/airblade-recomp/mc0` y `mc1` estan vacias. Eso sale de una traza de la recomp al guardar, o de la tarjeta real del usuario con la skill `console-saves`.

## (b) Implementacion

### `plat_memcard` (`include/plat_memcard.h`, `src/plat_memcard.cpp`)

Dos puertos = dos carpetas. Misma regla de raices que la recomp: raiz 0 con hoja `mc0` -> raiz 1 `mc1` hermana; otra hoja `X` -> `X_slot1`. La raiz la pasa quien llama (en M1: `<carpeta del ELF>/mc0` por defecto, como la recomp; nada se fija en el codigo).

API sincrona con el modelo "orden + sync" de libmc: cada orden termina al instante y deja el resultado pendiente; `plat_mc_sync` devuelve -1 si no habia nada pendiente (sondeo ocioso) y 1 con `cmd`/`result` si habia. Cubre las 19 llamadas `sceMc*`. No toca memoria del invitado: el pegamento de M1 traduce punteros (la tabla de directorio `plat_mc_dirent` tiene el layout exacto de `sceMcTblGetDir`, 64 bytes, comprobado con `static_assert`).

Compatibilidad con la recomp, **leida del codigo** (no ejecutada): ficheros normales con los bytes del juego; apertura por `fopen` con la misma tabla de modos (RDONLY/WRONLY/RDWR x CREAT/TRUNC/APPEND); `fwrite` + `fflush` en cada escritura; `GetDir` con `.` y `..` primero y el resto por nombre sin distinguir mayusculas; comodines `*` `?`; limite de 32 manejadores; `GetInfo` = tipo 2, 0x2000 clusters libres, formateada; `GetEntSpace` = 1024; slot distinto de 0 invalido; codigos de resultado iguales.

Diferencias deliberadas (seguridad): `..` nunca sale de la raiz, y un nombre con `:` o caracteres de control se rechaza (`-5`) en lugar de poder escapar de la carpeta en Windows. Las fechas de `GetDir` salen del reloj del sistema en hora local, como la recomp; la tarjeta real usa otra cosa y el juego solo las muestra **(hipotesis)**.

**Criterio del plan "guardar y cargar produce un fichero identico al de la recomp"**: como la recomp guarda con stdio directo, lo que hay que garantizar es que el arbol de carpetas resultante sea igual byte a byte. `plat_mc_compare_trees` (y la herramienta `mc_compare <A> <B>`) comparan dos tarjetas (arbol, nombres, tipo y contenido; ignoran fechas). `test_memcard` lo usa con una escritura de referencia hecha con stdio puro y comprueba que un cambio de un byte se detecta. **La comprobacion contra la recomp de verdad** (mismas acciones del juego en las dos, luego `mc_compare mc0_port mc0_recomp`) **queda pendiente** hasta que el binario nativo llegue a guardar (M1+M2); hoy no hay forma de lanzar la accion de guardar en ninguno de los dos sin datos del juego.

### `plat_video` (`include/plat_video.h`, `src/plat_video.cpp`)

libavcodec: parser MPEG-2 + decodificador, hilo unico (determinista), imagenes copiadas a una cola propia y entregadas en orden de presentacion. Modos: flujo (`open_stream` + `feed` + `feed_end`, con `NEED_DATA` cuando falta entrada, como el DMA al IPU), fichero (lee por trozos de 64 KB; los 536 MB de `MAKINGOF` no se cargan enteros) y memoria. `plat_video_frame_to_rgba` convierte a RGBA8888 (BT.601 limitado, alfa 0x80); `plat_video_frame_to_rgba_mb` lo reordena por macrobloques 16x16 como lo entrega `sceMpegGetPicture` **(hipotesis: orden y formula de color no comprobados contra el IPU real; el CSC del IPU no es necesariamente identico a esta formula)**.

CMake busca libavcodec/libavutil por `pkg-config` (libavformat solo para el oraculo de las pruebas). Si no estan, el modulo compila sin backend: `plat_video_available()` = 0, las funciones fallan limpio y `test_video` sale con 77 (SKIP en ctest). Sin ninguna ruta fijada.

### Pruebas (todas pasan en este Mac: clang, FFmpeg 8.x, `-j2`)

- `test_memcard` (sin datos del juego, carpeta temporal propia, tambien limpio con ASan+UBSan): raices, guardado/recarga, banderas, `seek`, `GetDir` (orden, atributos, comodines, solo contar), `chdir`, escape con `..` y `C:`, rename/delete/no-vacia, 32 manejadores, tarjeta 1 independiente, unformat/format, `sync` ocioso = -1, y comparacion de arboles.
- `test_video`: genera su MPEG-2 con el codificador de libavcodec (64x48 y 640x512, I/P/B) y comprueba: orden de presentacion y PSNR >= 28 dB frente al origen (medido 37-40 dB; umbral **propuesto**), memoria == fichero == flujo por trozos de 1/7/997/65536 bytes, y **diferencia maxima por muestra = 0 frente a un oraculo independiente** (libavformat + decodificador generico). Con `AB_M2V_FILE=<ruta>` (y `AB_M2V_FRAMES`) prueba un `.M2V` real, solo lectura.

Medido a mano sobre los `.M2V` reales (no entra en el test automatico por ruta): numero de cuadros de `SPLASH`, `MENUBASE`, `GALLERY`, `CREDITS` igual al de `ffmpeg` (323 / 1267 / 1636 / 1073), y el volcado yuv420p completo de `SPLASH` y `MENUBASE` con `m2v_probe ... raw` tiene el mismo md5 que `ffmpeg -pix_fmt yuv420p -f rawvideo`.

**Lectura honesta del criterio "diferencia por muestra frente a ffmpeg"**: da 0 porque el decodificador *es* FFmpeg; no prueba que el IPU real de PS2 produzca esos mismos valores (su IDCT no es necesariamente bit-exacta con la de FFmpeg). Para el port basta, porque el objetivo es ver la misma imagen que la recomp (que tambien usa FFmpeg); si se quisiera fidelidad al hardware, haria falta un oraculo del IPU (p. ej. capturas de PCSX2). **(hipotesis)** de que la diferencia visible sea irrelevante.

### Herramientas

- `m2v_probe <fichero> [max] [raw]`: una linea por cuadro (indice, tipo, CRC-32) o planos yuv420p por stdout.
- `mc_compare <A> <B>`: compara dos carpetas de tarjeta.

## Como enlazarlo (para M1/M2/M4)

- `sceMcInit/Open/...` -> `plat_mc_*`; el resultado de `sceMcSync(mode, &cmd, &res)` sale de `plat_mc_sync`.
- `_sendDataToIPU` / DMA canal 4 -> `plat_video_feed`; callback Nodata cuando `plat_video_next_frame` devuelve `NEED_DATA`; fin de fichero -> `plat_video_feed_end`; `sceMpegGetPicture` -> `next_frame` + `to_rgba_mb` al buffer del juego; `sceMpegReset/ClearRefBuff` -> cerrar y reabrir el flujo (no hay `reset` propio todavia).
- El audio (`.VAG`) y la sincronia con el reloj de vblank (3.9) no estan aqui: el cuadro 25 fps se presenta por vblank PAL (50 Hz -> uno de cada dos) **(hipotesis)**.
